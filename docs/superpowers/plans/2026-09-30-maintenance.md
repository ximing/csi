# CSI 架构维护实施计划

**目标：** 同步架构文档，统一扩展关闭/detach 清理入口，补强已有工具一致性检查，单独交付超时恢复设计。
**范围：** 用户选定的第 1、3、4、5 项；不改会话持久化、不改变监听和鉴权实现、不实现新的超时协议。
**架构：** 生命周期模块统一接收 Chrome 事件，各状态模块注册自己的清理函数；显式关闭也走同一分发入口。保留已有工具检查脚本与 CI，增加失败保护及运行时注册校验。

- [x] 文档：核对 config/server/protocol，更新中英文 README 和根指令的默认值与可配置行为。
- [x] 生命周期：先测试关闭、detach、重复清理、失败隔离；迁移 refs/debugger/frames/queue/network/opt-out，各模块不清其他模块状态；关闭失败且 tab 存活时保留队列。
- [x] 工具检查：保留五源清单和参数比较，拒绝重复或空解析；增加故意破坏输入的回归测试；运行时工具清单与 Go/MCP/协议对照。
- [x] 超时设计：描述现状，确定操作身份、等待与执行状态、取消边界、会话排队、迟到结果、重连/重启和兼容迁移；明确为未实现提案。
- [x] 验证：extension 全量测试/typecheck/build，daemon go test ./...，一致性检查及检查器负向测试，git diff --check。

重点回归：detach 不释放仍在执行的标签队列；重复关闭无害；一个清理器异常不阻止其他模块；新工具缺注册或重复名称会失败；调用方超时不被设计成无副作用保证。

验证结果：扩展 594 测试通过，typecheck/build 通过；daemon go test ./... 通过；检查器 9 个负向测试及工具/参数/技能链接检查通过；官网构建通过。未执行真实 Chrome e2e，未发布。
